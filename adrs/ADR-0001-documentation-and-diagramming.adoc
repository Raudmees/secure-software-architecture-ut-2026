= ADR-0001: C4 model with Structurizr for architecture diagrams, AsciiDoc for documentation
:toc:

== Status

Accepted

== Context

We need a consistent way to visualize and document the structure of the Citizen Services Portal. 

C4 context and container diagrams are the first diagrams we will be required to draw. Diagrams must use consistent names for 
systems, containers and actors, matching the glossary, drivers and risk register.

If every team member draws in a different style or tool, diagrams become inconsistent and hard to 
review, and names drift between diagrams and documents.

== Decision

* We use the C4 model as the notation for all architecture diagrams
* We write the diagrams as code with Structurizr, the diagrams are stored under /diagrams
* Each diagram is committed as source code together with a SVG export.
* Architecture documentation is written in AsciiDoc in the repository

== Alternatives considered

* *PlantUML*: diagrams as code and easy to start with, but each diagram is a
  separate file, so the context and container diagrams can drift apart (for example different
  names for the same element) unless names are kept in sync by hand.
* *draw.io*: easy to start with, but files are hard to review in Git and nothing keeps names 
  consistent between diagrams.
* *IcePanel*: a model-based C4 tool, so names stay consistent between views, with a visual,
  interactive editor.

== Consequences

* Positive: all diagrams follow the same C4 levels and visual styles. Diagram sources are plain text, 
  so changes are visible in Git diffs and reviewable in pull requests. Documentation and diagrams 
  live together in the repository. The created diagrams are consistent with each other

* Negative or risks: The team has to learn the Structurizr DSL and its tooling. Diagrams must be exported to SVG for reviewers, and exports can become outdated if the DSL changes but is not re-exported.

* Follow-up actions: 

** Keep element names identical to /docs/glossary.adoc.
** Re-export the SVG images whenever the DSL changes, at least before each checkpoint.
