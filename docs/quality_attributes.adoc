== 2. Architecture-critical drivers

The following five drivers are architecture-critical: decisions about them shape the overall
structure of the portal and are expensive to change later.

* *QA-1* Authorization and confidentiality
* *QA-2* Privacy and data minimization
* *QA-3* Availability and resilience
* *QA-4* Auditability and accountability
* *QA-5* Evolvability and interoperability

== 3. Trade-offs between important attributes

=== 3.1 Auditability and observability vs. privacy

Auditability and observability require recording information about system activity, while privacy
and data minimization require limiting the amount of personal information stored. Logs and audit
records therefore need enough information to reconstruct relevant actions without unnecessarily
copying sensitive document contents, messages or personal data into logging systems.

=== 3.2 Security and privacy vs. usability

Stronger security controls can reduce usability. For example, frequent re-authentication, short
sessions, additional authorization checks or restrictive handling of personal information can
make public services more cumbersome for citizens. The architecture should minimize
unnecessary user friction while ensuring that sensitive operations do not weaken authentication,
authorization or privacy controls for convenience.

=== 3.3 Availability and resilience vs. security and privacy controls

Availability requires the portal to keep working when parts of it fail, while security requires that
protected operations are always properly authenticated, authorized and logged. These pull in
opposite directions when a security-relevant dependency becomes unavailable: if the service is
down, the portal must choose between rejecting requests it cannot fully verify (secure but
unavailable) and serving them with reduced verification (available but potentially unsafe).

This can be solved by degrading functionality rather than controls. When a dependency needed
to make a safe decision is unavailable, the affected operation is refused, while unrelated
capabilities remain fully available.
