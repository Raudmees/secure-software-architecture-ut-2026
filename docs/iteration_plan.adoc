= Project iteration plan
:toc:
:toclevels: 2

Risk IDs refer to link:../risk/risk_register.adoc[risk/risk_register.adoc]. The phases follow
the RUP lifecycle and address higher-priority risks first. A risk may appear in more than one
phase when early validation is followed by implementation or final verification.

== Phase 1. Inception

Agree the scope and initial architecture, and reduce the High/High risks that could invalidate the project direction.

[cols="1,3,3",options="header"]
|===
|Risk |Action |Artifact or evidence

|R10
|Define the initial system context, containers and one main end-to-end flow.
|Initial C4 diagrams and sequence diagram.

|R13
|Define which case data and documents are handled by the portal and which remain with agencies.
|Data ownership and system-of-record boundaries.

|R06
|Investigate the signing integration and validate its riskiest step with a PoC or mock.
|Signing sequence and technical spike.

|R09
|Select representative external systems, compare their interfaces and test the adapter approach.
|Interface comparison and adapter PoC or mock.

|R11
|Estimate users, requests and data volumes, and define the peak-load scenario.
|Capacity assumptions and target workload.

|R12
|Define the authorization boundary and validate one delegated-access path.
|Delegation model and small authorization spike.
|===

== Phase 2. Elaboration

Establish the executable architecture baseline and reduce the remaining high-impact risks.

[cols="1,3,3",options="header"]
|===
|Risk |Action |Artifact or evidence

|R01
|Model and validate one national eID authentication flow.
|Authentication sequence and PoC or mock.

|R02
|Evaluate the case-management approach with one representative workflow.
|Workflow model and technology decision.

|R04
|Prototype document upload and antivirus scanning, including failure handling.
|Document-processing PoC.

|R07
|Define audit events and trace one action across components.
|Audit-event model and example trail.

|R08
|Define security for one third-party API interaction.
|API authentication, authorization and audit model.

|R10
|Connect the main components into an executable architecture baseline.
|Representative vertical slice.

|R14
|Confirm fallback requirements for residents without eID and model one valid path.
|Fallback authentication or service-path model.
|===

== Phase 3. Construction

Build the system on the validated architecture and integrate the selected mechanisms.

[cols="1,3,3",options="header"]
|===
|Risk |Action |Artifact or evidence

|R02, R04, R06
|Implement the selected case, document-scanning and signing flows.
|Integrated feature flows and tests.

|R03
|Implement the notification abstraction with at least two channels.
|Notification integration and retry tests.

|R05
|Implement representative document-retention rules.
|Automated retention or application-level fallback.

|R07, R08, R09, R12
|Apply the audit, API-security, adapter and delegation mechanisms across the built features.
|Component and integration tests.

|R10
|Complete the main end-to-end citizen-service flow.
|Integrated vertical slice.
|===

== Phase 4. Transition

Validate the completed system under realistic load and failure conditions, and prepare it for operation.

[cols="1,3,3",options="header"]
|===
|Risk |Action |Artifact or evidence

|R11
|Run load tests using the capacity estimates and peak-load scenario from Inception.
|Load-test results and identified bottlenecks.

|R03, R04, R09
|Test notification-provider, antivirus-service and agency-system failures and recovery.
|Failure and recovery test results.

|R07, R10
|Validate observability and the end-to-end flow in the deployment environment.
|Operational and end-to-end validation results.
|===
