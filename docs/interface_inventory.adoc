= Interface Inventory

The interface names below are the arrow labels of the
link:../diagrams/c4_containers.svg[container diagram], and producers and consumers are named as
on that diagram.

[cols="1,3,1,2,2,2,2,2",options="header"]
|===
|ID |Interface |Kind |Producer |Consumer |Protocol |Auth mechanism |Versioning (draft)

|IF-1
|Portal Citizen API
|API
|API gateway
|Citizen web app
|HTTPS/JSON
|Resident session token from eID login, checked by API gateway
|/v1 in URL - only additive changes within v1

|IF-2
|Portal Third-party API
|API
|API gateway
|Third-party service providers
|HTTPS/JSON
|OAuth 2.0 client credentials
|/v1 in URL - after /v2 is released, /v1 stays for 6 months (R16)

|IF-3
|Identity & Access API
|API
|Identity & access
|API gateway
|HTTPS/JSON
|mTLS service identity
|Internal - changed together with the consumer

|IF-4
|Portal Backend API
|API
|Portal backend
|API gateway
|HTTPS/JSON
|mTLS service identity - carries the resident's checked token
|Internal - changed together with the consumer

|IF-5
|Audit Transparency API
|API
|Audit service
|API gateway
|HTTPS/JSON
|mTLS service identity - carries the resident's checked token
|Internal - changed together with the consumer

|IF-6
|Mandate Check API
|API
|Agency integration
|Identity & access
|HTTPS/JSON
|mTLS service identity
|Internal - changed together with the consumer

|IF-7
|Integration Data API
|API
|Agency integration
|Portal backend
|HTTPS/JSON
|mTLS service identity
|Internal - changed together with the consumer

|IF-8
|Delivery Report API
|API
|Portal backend
|Agency integration
|HTTPS/JSON
|mTLS service identity
|Internal - changed together with the consumer

|IF-9
|Submission Queue
|Event
|Portal backend
|Agency integration
|Message queue
|mTLS to the broker, only Portal backend may publish, only Agency integration may consume
|Internal - schemaVersion field in each message

|IF-10
|Audit Event Stream
|Event
|All containers
|Audit service
|Message queue
|mTLS to the broker, all containers may publish, only Audit service may consume
|Internal - schemaVersion field in each message

|IF-11
|Agency API
|Integration
|Agency back-end e-services
|Agency integration
|HTTPS/JSON
|mTLS
|/v1 in URL, defined by the portal - old version kept 6 months so agencies have time to update

|IF-12
|External Registry APIs
|Integration
|External registries
|Agency integration
|HTTPS, each registry's own API
|mTLS
|Set by each registry - adapter isolates changes

|IF-13
|Notification Provider APIs
|Integration
|Notification providers
|Portal backend
|HTTPS, each provider's own API
|API key per provider account
|Set by each provider - adapter isolates changes

|IF-14
|eID Login API
|Integration
|National eID / OIDC identity provider (TARA)
|Identity & access
|OpenID Connect (OIDC)
|OIDC client registration with TARA (client ID and secret)
|Set by the provider (TARA)

|IF-15
|Digital Signing API
|Integration
|Digital signing service
|Portal backend
|HTTPS, provider's API
|Relying-party account issued by the signing service
|Set by the provider - adapter isolates changes
